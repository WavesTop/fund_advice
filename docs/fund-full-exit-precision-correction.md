# 基金配置回测：完整退出与检查时钟更正

更新：2026-10-14。发现并修复了基金配置研究引擎的完整退出状态问题。受影响的旧账户收益不能继续直接作为当前已核验的投资证据；冻结文件保留源码和输入用于审计，不覆盖或静默改数。

## 已确认的问题

此前目标权重归零时，计划卖出的是以40位精度相加的总份额，再从FIFO各批次扣除。即使现金金额核算误差小于原1e-8容差，最后一个批次仍可能留下极小的正份额。下次卖出该残余会产生待到账记录，到账又触发新的趋势检查，影响后续实际交易。

已确认的例子：9主题池、单赢家20日、无买卖费情景，黄金2026-03-25完整退出后剩余2e-36份；2026-03-30又赎回6.8144e-36元，2026-04-01因此多了一次风险与趋势检查。数额无经济意义，但检查日期和后续持仓可能有实质影响。不能把这条路径视为真实降费收益。

另有确定性小样本复现：常数净值2.157599、多次增加和减少批次，完整退出后旧实现留下1.3e-35份，并在非预定日额外调用策略。这个例子已成为回归测试，不能只用终值金额误差判断通过。

## 修复与核验

- 完整退出逐批精确消费所有可赎回份额，不以舍入后的总量截断最后批次。仍遵守确认、普通持有等待、FIFO和短持费用。
- 待执行订单仍不与新决策重叠，同代码也不会在等待中新增申购批次；没有利用未来净值或未来未知份额设定订单。
- 独立账本核验新增两项：目标为零的实际卖出须精确消费该可赎回批次；执行后不能保留本次完整退出应赎回的批次。极小残余也拒绝，不以金额容差放行。
- 回归测试证明完整退出后不留持仓、不产生残余赎回或虚假的到账检查，并拒绝人为留下低于旧金额容差的份额。

原指数价格、信号统计及成熟标签训练不因这个问题自动失效；需要重新核查的是使用 `backend/analysis/fund_allocation.py` 的动态账户收益、费用、日期、实际风险和涉及这些路径的结论。固定正权重配置或某些完整账户可能不受影响，必须实际重算确认，不能笼统宣布全部旧数字仍正确。

修正版费用诊断使用 `config/trend-friction-diagnostic-v2.json`，继承原设定并明确记录实现修复。输出为 `runtime/verification/trend-friction-diagnostic-v2.json.gz`，旧v1只作为更正前参照；逐项记录发生变化的原基线指标，不再要求错误状态下的收益保持不变。阶段新开户基线也重新计算，不复用可能受影响的旧结果。

当前仍未证明趋势评分有稳健投资优势，未改生产排名、数据库或实盘，未提交代码。修复计算不等于取得预测优势，修正版结果也仍受历史筛选和费用/确认/分红假设限制。

修正版已完成304个账户核验及828个持续账户切片检查，36组主基线中23组指标更正、13组完全一致。黄金残余赎回及2026-04-01伪检查已确认消失，见[修正版费用诊断](fund-trading-friction-diagnostic.md)。不把这个修复带来的收益变化算作策略创新。
