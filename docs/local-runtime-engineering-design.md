# 本地运行与工程保障开发方案

- 更新日期：2026-09-19
- 对应范围：整体技术架构 §3.6
- 实施计划：[本地运行与工程保障分阶段开发计划](local-runtime-engineering-plan.md)
- 当前结论：已有开发态前后端联合启动、回环地址绑定、健康接口、SQLite 迁移、部分采集运行记录、研究数据库一致性备份和测试配置；尚无面向日常使用的生产启动器、持久任务执行器、密钥管理、成套恢复、升级回滚和完整诊断。

## 1. 目标与范围

本阶段把已实现的页面、数据、研究、账本和复盘能力组织成可在单台个人电脑上可靠运行、停止、恢复、升级和备份的本地应用。首版坚持“小而可诊断”：React 构建产物、FastAPI、SQLite 和受控后台工作进程，不引入 PostgreSQL、Redis、Celery、Nginx 或 Docker 作为日常运行前提。

本阶段包含：

- 日常启动器、进程监督、就绪检查、停止和端口处理；
- 持久后台任务、互斥、进度、取消、重试、超时及异常恢复；
- 本机配置、密钥和 AI 调用边界；
- 数据库、原始资料、业务附件和必要配置的成套备份／恢复；
- 日志、健康、新鲜度、磁盘、资源和错误诊断；
- 依赖锁定、迁移、升级、回滚、自动测试和发布验收。

本阶段不改变各业务模块的计算规则，不把失败任务伪造成成功，也不通过补跑制造过去未真实发布的建议。业务幂等和版本语义仍由对应模块定义，任务层负责可靠执行。

## 2. 当前实现基线

| 已有能力 | 当前性质 | 尚缺内容 |
| --- | --- | --- |
| `scripts/start_local.py` | 同时启动锁定离线 Python API 与 Vite 开发服务器，处理 SIGINT/SIGTERM。 | 依赖已安装环境；使用开发服务器；无就绪等待、端口冲突指引、浏览器入口、日志文件或崩溃策略。 |
| FastAPI `/health` | 检查数据库连接、迁移版本、SQLite 信息和能力列表。 | 无工作进程、任务、磁盘、数据新鲜度、配置和降级状态；不能作为完整 readiness。 |
| SQLite 迁移 | 启动时自动应用顺序迁移，已有数据库与研究表。 | 无升级前强制备份、迁移预检、回滚／恢复编排和磁盘空间保护。 |
| 采集运行记录 | 板块／目录任务有跨进程互斥、进度、尝试记录和终态。 | 明确标注为“不是后台队列”；目标有限，无租约、心跳、通用取消和自动恢复。 |
| 研究数据库备份 | 使用 SQLite backup API，校验完整性、外键、原始资料哈希和快照清单，禁止覆盖。 | 只提供底层函数；未包含外部文件／配置清单，无恢复流程、保留策略和页面入口。 |
| 前端任务／备份设置页 | 有队列、取消、状态、演示导入导出和运行说明。 | 均为浏览器演示；不控制真实后台任务或完整备份。 |
| 工程测试配置 | Python `unittest`、Vitest、TypeScript、Prettier、Playwright 配置及锁定依赖存在。 | 仓库内未形成统一的一键验收与发布流水；实际运行环境可能偏离锁定版本。 |

## 3. 目标运行拓扑

```text
本地启动器
├── API / 静态前端服务（127.0.0.1，单一用户入口）
├── 后台工作进程（同一 SQLite 任务协议）
├── SQLite 数据库（WAL、短事务、单写入约束）
├── 原始资料与业务附件目录
├── 日志与诊断目录
└── 本机密钥存储或权限受限配置引用
```

日常模式由 FastAPI 提供构建后的前端静态资源，避免要求用户同时运行 Vite。开发模式保留当前前后端双进程和热更新。两种模式使用相同 API 契约和明确不同的配置档，不能让开发演示默认连接真实个人数据库。

默认只监听 `127.0.0.1`，随机或配置化选择未占用端口，并将实际入口反馈给用户。开放局域网访问属于未来能力，不能通过简单改为 `0.0.0.0` 默认开启。

## 4. 启动、监督与关闭

### 4.1 启动阶段

1. 解析并校验配置，确定数据目录且拒绝危险的根目录目标。
2. 检查依赖版本、目录权限、可用空间、数据库锁和上次异常退出标记。
3. 在需要迁移时创建可验证的升级前备份，再执行迁移和完整性检查。
4. 启动 API 与工作进程，等待内部就绪探针，不仅检查端口已监听。
5. 输出或打开本机入口；记录本次运行 ID、版本、配置摘要和进程信息。

任一步失败都停止本次新进程，保留已有数据并给出可执行说明。不能因前端打开成功就把数据库或工作进程标为可用。

### 4.2 运行监督

启动器监控子进程退出、心跳和资源状态。API 意外退出时停止接受新任务；工作进程退出时页面仍可只读查看本地数据，并显示后台不可用。自动重启必须有次数和时间窗口限制，避免崩溃循环。

### 4.3 有序关闭

关闭先停止接收新任务，再通知可取消任务，允许正在提交的短数据库事务结束，将长任务保存为可恢复或已中断状态，最后关闭 API。超过期限才强制结束，并在下次启动执行恢复扫描。

## 5. 持久任务系统

### 5.1 通用任务模型

| 字段 | 作用 |
| --- | --- |
| `task_id`、`task_type`、`target_key` | 稳定身份和业务目标。 |
| `state` | queued、running、cancel_requested、succeeded、partial、failed、cancelled、interrupted、blocked。 |
| `idempotency_key`、`input_hash` | 防止重复任务和确认相同输入。 |
| `created_at`、`not_before`、`started_at`、`finished_at` | 排队、调度和审计时间。 |
| `lease_owner`、`lease_until`、`heartbeat_at` | 检测失联工作进程并安全接管。 |
| `attempt`、`max_attempts`、`retry_policy` | 受控重试，区分瞬时与永久错误。 |
| `progress`、`result_ref`、`error_code` | 真实阶段／数量、业务结果及可诊断失败。 |
| `cancel_capability` | 是否支持取消及取消边界。 |

终态不可覆盖；重试创建 attempt 记录，任务本身保留完整历史。进度没有可靠总量时只保存阶段和已处理数量，不伪造百分比或剩余时间。

### 5.2 领取、互斥和幂等

工作进程以短事务原子领取到期任务并设置租约。业务目标互斥由 `task_type + target_key` 的活动唯一约束保证；跨任务共享的写入仍使用业务幂等键。租约到期不代表可以盲目重做：恢复器先查询业务提交结果，再决定完成、续跑或转为需人工处理。

采集、分析、模拟和复盘均通过同一任务协议，但各自定义检查点和可取消边界。API 请求不在连接生命周期内执行长采集。

### 5.3 失败、取消和恢复

- 网络超时、限流等可重试错误使用有上限的指数退避和随机扰动；数据格式、权限、无效配置等永久错误不自动重试。
- 取消是请求，不是立即成功。任务在安全检查点确认后进入 `cancelled`；已原子发布的结果按事实保留。
- 休眠、关机或崩溃后，启动恢复器检查过期租约、临时文件和业务结果；不能简单把所有 running 改成 queued。
- 补跑只生成当前真实运行结果。错过期间未发布的建议、AI 输出或前瞻观察不能补写成历史事实。

## 6. 配置、密钥与 AI 运行

### 6.1 配置分层

配置优先级建议为：内置安全默认值 < 本机配置文件 < 环境变量 < 当次命令参数。最终配置在启动时验证，诊断页只显示脱敏摘要。至少覆盖数据目录、端口、日志级别、任务并发、备份目录、数据更新策略和 AI 提供方引用。

业务策略参数不混入运行配置；其版本归 §3.3／§3.5。更改数据目录、备份目录或网络绑定属于高影响配置，需预检和明确反馈。

### 6.2 密钥

优先使用操作系统密钥链；不可用时使用权限受限的本机秘密文件，仅保存引用或密文，不写入数据库备份、导出、日志、任务输入、错误堆栈或前端本地存储。页面保存后只显示“已配置”、替换和清除。

### 6.3 AI 调用

每次调用保存提供方、模型、提示版本、资料类别、发送范围确认、时间、状态、用量和可得费用，不保存密钥。调用设置超时、限流、最大重试和并发上限；未知结果先查询或标记不确定，不盲目重复付费。

AI 未配置、断网、额度不足或输出校验失败时，本地基金浏览、账本和受支持的本地分析继续可用。旧 AI 结果只能按其原时间和版本读取，不能无标识地充当新结果。

## 7. 数据目录、备份与恢复

### 7.1 数据范围

数据根目录包含数据库、原始资料／附件、运行日志、任务临时区和版本清单；缓存与可重新下载内容单独标识。密钥不进入普通备份。所有路径先规范化并拒绝源目录、根目录、工作区根或已有非空目标等危险选择。

### 7.2 成套备份

备份流程：

1. 创建新的临时备份目录，不覆盖既有备份。
2. 使用 SQLite backup API 得到一致数据库快照，不直接复制 WAL 组合。
3. 按清单复制需要保留的原始资料和附件，逐项计算哈希。
4. 写入应用版本、模式版本、创建时间、范围、文件大小和哈希清单。
5. 运行数据库完整性、外键、业务引用及文件哈希检查。
6. 在同一文件系统原子发布，失败清理临时目录，旧备份不受影响。

支持完整备份和明确范围的个人记录导出，两者在页面上必须分开。保留策略只删除明确选中的旧备份，默认不自动清理唯一可恢复副本。

### 7.3 恢复

恢复先在隔离临时目录解包和校验，展示备份时间、应用／模式版本、包含范围及将替换内容；建议并可一键先备份当前数据。确认后停止写入和工作进程，关闭连接，原子切换数据目录，再迁移兼容版本、重建派生缓存并执行健康检查。

任何校验或启动失败都回到原数据目录并保留失败诊断。恢复后不得自动解除遗留 running 任务；需按租约和原进程状态执行恢复审计。

## 8. 健康、日志与诊断

### 8.1 探针

- `liveness`：进程事件循环可响应，不访问外部网络。
- `readiness`：数据库可用、迁移兼容、必要目录可读写；工作进程状态单独返回。
- `capabilities`：基金浏览、采集、研究、账本、模拟、复盘、AI 等按实际依赖给出 available／degraded／unavailable 及原因。

现有 `/health` 可兼容保留，并逐步拆分上述语义。探针不得包含密钥、个人资产、原始资料正文或详细内部路径。

### 8.2 日志

结构化日志包含运行 ID、任务 ID、请求 ID、模块、错误代码和耗时；个人输入、持仓、笔记、Authorization、密钥及完整 AI 请求默认脱敏。日志轮转和总量有上限，用户可导出经过脱敏的诊断包。

### 8.3 状态页面

设置页展示服务、工作进程、数据库模式、最近备份、数据新鲜度、任务失败、磁盘空间和应用版本。对用户给出可理解的恢复动作，技术细节置于展开区。资源阈值只是预警，不能虚报精确剩余时间。

## 9. 升级、依赖与发布

- Python 和 Node 版本以项目锁定范围为准；安装、构建和测试均使用锁文件，禁止发布时隐式升级依赖。
- 每次发布包含应用版本、前端构建、迁移版本、兼容范围、校验和及发布说明。
- 升级预检备份、磁盘、数据库完整性和配置；迁移失败自动恢复旧数据与旧应用入口。
- 不承诺一般意义的迁移回滚 SQL；数据回退依赖经过验证的升级前备份。新版本写入后直接启动旧二进制前必须经过兼容检查。
- 开发态和日常态使用不同入口；发布包不得依赖全局 Vite、未锁定 Python 或仓库源码热更新。

## 10. 测试与验收

### 10.1 自动验证层次

1. 纯逻辑：配置、路径、重试、状态机、脱敏和清单。
2. 存储：迁移、任务领取／租约、并发互斥、备份／恢复及损坏注入。
3. 进程：启动、就绪、端口占用、子进程崩溃、有序／强制关闭和重启恢复。
4. 业务集成：采集、分析、模拟、复盘使用统一任务并保持幂等。
5. UI／端到端：从首次启动、任务状态、失败恢复、备份、升级到完整业务流程。

### 10.2 故障注入

至少覆盖断网、接口限流、数据库忙、磁盘不足、备份目标已存在、文件哈希错误、进程被杀、系统休眠、端口占用、迁移中断、AI 超时及恢复失败。测试确认数据不被覆盖、终态真实、旧资料可读且错误可操作。

### 10.3 完成条件

在一台干净的受支持机器上，可通过一个日常入口完成安装／启动、健康检查、业务使用、停止、重启恢复、完整备份、恢复预览和恢复；异常场景不丢失已确认事实、不重复业务写入、不泄露密钥。开发启动脚本可用或单项单元测试通过都不代表 §3.6 完成。

## 11. 安全默认值

首版无注册登录的前提只适用于回环地址上的单用户本机访问。写请求校验可信来源并限制请求体和上传大小；文件导入按不可信输入处理；下载资料和 AI 返回不作为可执行指令。路径、压缩包和文件名防止目录穿越。所有外发资料先按用户确认范围最小化。
