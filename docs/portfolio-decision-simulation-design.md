# 持仓、决策记录与模拟对比开发方案

- 更新日期：2026-09-19
- 对应范围：整体技术架构 §3.4
- 实施计划：[持仓、决策记录与模拟对比分阶段开发计划](portfolio-decision-simulation-plan.md)
- 当前结论：前端已具备明确标识的演示录入、校验、更正、决定关联和对比页面；正式账本、费用计算、模拟执行、收益核算及后端持久化尚未实现，演示数据不能升级为真实记录。

## 1. 目标、范围与边界

本阶段建立一份可追溯的真实个人账本，并在相同资金和执行口径下比较用户实际结果与短期、中期、长期三个独立模拟结果。系统必须回答“当时建议了什么、用户决定了什么、实际发生了什么、模拟会发生什么、差异来自哪里”，而不是只展示最终收益数字。

本阶段包含：

- 个人投资条件、账户现金、初始持仓、逐笔申请／成交／确认／到账、分红和份额变化；
- 版本化费用及交易规则、批次持有期、费用估算与确认；
- 建议、用户决定、实际交易之间的多对多关联及追加式更正；
- 单次建议评估和持续跟踪模拟；
- 实际与模拟的资产、收益、费用、风险和执行差异；
- 对 §3.3 提供可独立调用的费用试算、账户快照与可执行性检查服务；向 §3.5 提供不可变复盘输入。

本阶段不包含真实券商／基金销售交易、不自动采纳建议、不生成市场研究、不自动启用策略。职责边界如下：

| 相邻范围 | 本阶段的关系 |
| --- | --- |
| §3.2 数据与存储 | 消费基金身份、净值／行情、分红拆分、交易日历和规则版本；不从名称猜测基金或补造缺失价格。 |
| §3.3 投资分析 | 接收固定建议版本和操作草案，返回费用、批次、资金及可模拟结果；“采纳”不等于成交。 |
| §3.5 复盘改良 | 输出决定、实际／模拟执行、收益和差异证据；策略候选及启用由 §3.5 管理。 |
| §3.6 本地运行 | 复用持久任务、备份恢复、配置和运行诊断；不在业务模块自建第二套队列。 |

## 2. 当前实现基线

以下能力已经存在，但均属于浏览器演示范围：

| 已有能力 | 当前性质 | 正式化缺口 |
| --- | --- | --- |
| 持仓／交易表单 | 已实现日期、金额、份额、状态、渠道校验，支持初始持仓、买卖、现金、分红和份额变化。 | 数据只在浏览器 `localStorage`；没有基金身份外键、服务端幂等、余额或可用份额核算。 |
| 更正与撤销 | 通过追加记录保留原记录，导入时检查更正链循环和分叉。 | 没有正式事件账本、并发控制、审计主体和影响重算。 |
| 费用规则表单 | 可校验日期、区间重叠、期限缺口、费率和来源。 | 未实现规则版本选择、申购／赎回／场内成本公式和实际计费。 |
| 决定记录 | 支持全部／部分采纳、未采纳、暂不操作，能关联现有演示交易。 | 引用的是演示建议；没有正式建议修订外键、决定变更历史和 API。 |
| 收益对比页面 | 有四条曲线、三周期表格、时间线和复盘入口。 | 数值来自固定样例，不由账本或模拟计算。 |
| 演示导入导出 | 有结构、大小、引用、更正链和版本采用历史校验。 | 不是数据库备份，不可作为真实账本恢复机制。 |

## 3. 核心业务原则

### 3.1 一份真实账本，三个独立模拟账户

用户只有一份实际账户账本。短期、中期、长期模拟分别拥有独立的初始资金、现金、持仓、订单和费用，不能把三份模拟资金或收益相加，也不能把一个周期未使用的现金自动借给另一个周期。

每次比较记录 `comparison_scope`：实际账户、模拟账户、起止时点、外部现金流政策、估值政策、费用政策、数据截止时点和版本。条件不一致时各自展示结果，但不计算直接差额。

### 3.2 事实事件与派生状态分离

申请、成交、确认、到账、分红、拆分、更正等事实以追加事件保存；持仓余额、可用份额、现金、成本和收益是按指定截止时点计算的派生结果。不得直接修改历史事实来“修正余额”。

更正记录引用被更正事件和原因，新旧记录均保留。重复提交通过调用方幂等键和业务指纹拦截；建议与交易的多个关联只产生引用，不复制交易或重复扣费。

### 3.3 已确认、估算和未知分开

金额、份额、费用、成交日、确认日和到账日分别保存状态及来源：

- `confirmed`：有用户确认单或受支持来源；
- `estimated`：按冻结规则和当时数据计算；
- `pending`：已申请但尚未确认；
- `unknown`：信息不足，不能按零处理；
- `reversed`：由追加更正失效，不删除原记录。

估算转为确认时追加确认事件并保留差异。未知费用、未知成交价或待确认份额不得进入“已确认资产”而不作标识。

### 3.4 精度、单位与时间

- 金额、份额、净值、费率均使用十进制字符串进入接口，后端使用 `Decimal`；数据库保存规范化十进制文本或经设计确认的整数最小单位，不使用二进制浮点记账。
- 每个字段明确币种和单位；费率不与金额共用字段。计算过程保留高精度，只在规则规定的结算边界舍入，并保存舍入模式。
- 区分业务日期、市场时区时间、申请时间、成交时间、确认时间、到账时间、记录时间和修改时间。事后补录不能伪装成当时已知。
- 持有天数、交易日和截止时间由版本化日历／规则服务计算，不能用简单自然日差替代。

## 4. 领域模型与存储

### 4.1 账户和账本

建议的核心对象如下；最终表名可沿用仓库命名规范，但语义必须保持。

| 对象 | 关键内容 |
| --- | --- |
| `portfolio_account` | 本地账户、币种、启用时间、状态；首版可只有一个实际账户。 |
| `portfolio_condition_revision` | 现金、计划追加资金、风险、集中度、期限、渠道及生效时间；旧版本不可覆盖。 |
| `ledger_event` | 事件类型、基金份额身份、金额、份额、业务时间、状态、来源、幂等键、记录时间。 |
| `trade_lifecycle` | 申请、成交／净值、确认、到账的关联及每步状态；允许部分确认和失败。 |
| `position_lot` | 由已确认买入／初始持仓形成的批次、剩余份额、持有起点和成本完整性。 |
| `lot_allocation` | 卖出对批次的分配及规则版本；自动分配结果可由用户确认或更正。 |
| `fee_rule_revision` | 基金份额、渠道、费用类型、区间边界、有效期、来源和确认状态。 |
| `fee_charge` | 规则版本、计费基数、计算明细、舍入、估算／确认状态及关联事件。 |

初始持仓允许只有份额和快照日期，但必须标为成本／历史不完整；这类记录可用于当前仓位，不得据此给出完整历史收益。

### 4.2 建议、决定和操作关联

| 对象 | 约束 |
| --- | --- |
| `decision` | 引用不可变 `advice_revision_id`、周期、选择、用户理由、计划金额／仓位和记录时点。 |
| `decision_revision` | 用户改变决定时追加版本，原决定可读；状态变化不覆盖原理由。 |
| `decision_trade_link` | 决定与账本事件多对多关联；包含关联角色和创建时间，不拥有交易金额。 |
| `independent_trade_note` | 无建议的自主交易仍能进入账本和复盘，不能强制伪造建议来源。 |

基金身份必须引用 §3.2 的稳定份额标识；代码只作展示和输入定位。历史建议读取固定修订，不能用当前建议内容替换。

### 4.3 模拟与比较

| 对象 | 关键内容 |
| --- | --- |
| `simulation_run` | 模式、周期、建议／策略版本、输入快照、规则、日历、价格政策、生成时点和状态。 |
| `simulation_account` | 独立初始资产、现金和持仓；一个运行不得跨周期共用资金。 |
| `simulation_order` | 计划、校验、执行／跳过、原因、可用数据和实际采用价格。 |
| `simulation_ledger_event` | 与真实账本同语义的模拟事件，但物理身份和来源明确隔离。 |
| `valuation_point` | 截止时点资产、现金、应收应付、缺价和覆盖状态。 |
| `comparison_run` | 实际与一个模拟的统一期间、外部现金流映射、指标、可比性及不可比原因。 |

运行保存输入和实现版本哈希。相同幂等键只能得到同一运行；规则或输入变化创建新运行，不能静默改写旧结果。

## 5. 费用、批次与交易生命周期

### 5.1 共享费用服务

对外提供不依赖个人建议的费用试算接口，输入至少包含基金份额、渠道、动作、申请金额或份额、申请／退出时点、批次及规则截止时点，输出：

- 命中的规则版本和区间边界；
- 计费基数、逐项费用、舍入和合计；
- 已确认／估算／未知状态；
- 缺失规则、区间冲突或日期不确定等阻塞原因。

管理费、托管费等已体现在公布净值中的费用不得再次扣除。场外申赎、销售服务费适用性、场内佣金、价差及冲击成本分项表达；首版未支持的成本保持未知。

### 5.2 批次处理

卖出前验证已确认可用份额。赎回费用按实际分配批次的持有期计算；默认批次政策必须显式版本化，不能暗含 FIFO。部分卖出保留剩余批次，分红再投资形成新批次。初始持仓缺少买入日期时，依赖持有期的费用不能假定最低费率。

### 5.3 执行状态

场外基金至少区分申请、截止时间归属、未知净值、确认和到账；ETF 至少区分委托假设、成交／未成交、价格、佣金和结算。限购、停牌、最低金额、份额不足和价格缺失均产生可查询的失败或跳过记录。

## 6. 模拟协议与防未来信息

### 6.1 两类模拟

- **单次建议评估**：冻结一次建议及其当时个人快照，观察按建议执行后的独立结果。
- **持续跟踪**：按预先定义的接入规则，只消费当时真实保存且有效的后续建议；错过的建议不能事后补造成当时操作。

历史建议回放、独立策略试验和事后回测使用不同 `simulation_mode`。AI 事后重建必须标明可能包含后见知识，不能与真实保存的 AI 输出混为前瞻结果。

### 6.2 执行政策

每个运行冻结：可知时点、申请截止、下一个可执行时点、价格／净值来源、缺价处理、分红政策、费用规则、现金约束、最小交易、部分执行、退出和过期策略。运行只读取 `known_at <= decision_time` 的输入；结果期价格仅用于估值或按政策执行，不能反向影响决策。

遇到无法成交时记录原因，不使用之后更有利的价格自动补单。是否继续等待、取消或在下一可执行点重试必须由冻结政策决定。

## 7. 收益与可比性

### 7.1 基础恒等式

任一估值点：

`账户资产 = 现金 + 持仓市值 + 应收款 - 应付款`

比较期间收益金额：

`收益金额 = 期末资产 - 期初资产 - 期间外部净流入`

外部净流入包含用户入金减出金；买卖、费用、分红属于账户内部投资活动，不重复作为外部现金流。初始持仓成本未知时仍可从共同估值起点比较，但明确限制其历史收益解释。

### 7.2 收益率与风险

首版曲线和跨现金流比较采用版本化的时间加权收益口径；资金加权收益在现金流及日期完整时作为补充。最大回撤、波动和换手仅在数据密度和期间满足要求时计算，否则返回不足原因。所有指标保存算法版本、输入范围和覆盖。

### 7.3 可比条件

只有基金范围、起止时点、初始资产、外部现金流、估值来源、缺价政策和费用口径可对齐时，才显示“模拟 − 实际”的金额及百分点差。若模拟从更晚日期开始或实际记录不完整，应分别展示，不给出误导性直接差值。

差异至少拆分为操作时点、基金选择、仓位／现金使用、费用、无法成交和数据缺失；不能把残差强行解释为用户或系统判断优劣。

## 8. 服务接口

建议采用 `/api/v1`，写接口要求 `Idempotency-Key`，并返回稳定对象 ID、版本和保存状态。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v1/portfolio/conditions` | 读取当前条件、追加条件版本。 |
| `GET/POST /api/v1/ledger/events` | 查询或追加账本事件；更正使用独立动作而非覆盖。 |
| `POST /api/v1/ledger/events/{id}/corrections` | 追加更正／撤销及原因。 |
| `GET /api/v1/portfolio/snapshots` | 按截止时点取得已确认、待确认及未知部分。 |
| `POST /api/v1/fees/quotes` | 独立费用试算。 |
| `GET/POST /api/v1/decisions` | 查询或保存决定及版本。 |
| `POST /api/v1/decisions/{id}/trade-links` | 建立关联，不复制交易。 |
| `POST /api/v1/simulations` | 创建单次或持续模拟运行。 |
| `GET /api/v1/simulations/{id}` | 查询执行、跳过、费用和估值明细。 |
| `POST /api/v1/comparisons` | 建立实际与单个周期模拟的可比结果。 |

列表接口支持稳定分页、时点、状态和基金筛选。读取历史对象默认返回原版本；查看当前基金资料必须走显式入口。

## 9. 页面接入

现有“我的持仓”“建议与决策”“收益与复盘”页面布局可保留，正式接入时必须移除对应区块对演示状态的依赖：

1. 持仓页读取账户快照和逐笔事实，分别展示已确认、待确认、未知及历史不完整。
2. 决定保存引用正式建议修订；记录决定后不改变持仓，实际操作另行录入或关联。
3. 收益页由比较接口返回曲线、表格和可比性，不再引用固定 `reviewSamples`。
4. 所有写入显示提交中、结果不明、重复请求定位原结果和失败保留输入。
5. 演示入口继续显式隔离，演示数据不得混入正式 API 或数据库。

## 10. 测试与验收

### 10.1 必测算例

- 同基金多批买入、部分卖出、边界日赎回费、分红再投资及剩余批次；
- 申请日、确认日、到账日跨节假日，截止前后采用不同净值；
- 初始持仓只有份额、费用未知、价格缺失、限购、停牌和部分成交；
- 重复提交、保存超时后重试、更正链、关联多个决定且只记账一次；
- 外部入金不计为收益，净值内含费用不重复扣除；
- 三个模拟账户资金隔离，无法成交记录可追溯；
- 未来数据注入、历史规则修订和新建议不得改变旧模拟；
- 实际优于模拟、期间不同和覆盖不足均如实显示。

### 10.2 完成条件

正式完成必须同时满足：真实记录后端持久化；金额与份额独立算例复核；费用与交易生命周期可解释；旧建议、决定、交易、模拟和比较可按原版本读取；备份恢复后引用完整；端到端页面不依赖演示样例。界面存在、表单可点或合成测试通过，均不能单独代表正式账本和模拟完成。

## 11. 安全与限制

个人资产、决定和备注默认只保存在本机，不进入日志或 AI 输入。调用 AI 前由 §3.6 的发送范围控制剔除或最小化个人数据。接口只绑定本机并校验写请求来源；导出文件提示敏感内容。系统提供研究、记录和模拟，不保证收益，也不执行真实交易。
