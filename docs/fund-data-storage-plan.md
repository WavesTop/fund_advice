# 基金数据与存储：分阶段开发与复查计划

- 更新日期：2026-09-13
- 对应范围：整体技术架构 §3.2，实施要求以[基金数据与存储开发文档](fund-data-storage-design.md)为准。
- 当前进度：开发文档已完成并在本地提交（26c5d7a）；D0 已通过；D1.1 待复查，并穿插实现 D1.5、D1.6、D1.8 以及 D2.1、D2.2、D2.5、D2.6 的最小真实数据切片；其余能力未开始。
- 使用方式：按小阶段编号逐次执行；每项完成实现、针对性验证和交付说明后，交给用户复查，再开始下一项。

## 1. 执行与复查规则

### 1.1 一次执行的范围

1. 默认一次执行一个小阶段，例如“执行 D1.2”；不自动连做整个大阶段或进入下一小阶段。
2. 如果只指定大阶段，例如“开始 D1”，从该大阶段第一个满足前置条件、尚未完成的小阶段开始，交付后暂停；明确指定连续执行范围时按用户指定范围进行。
3. 每项包含必要实现、调用方调整、接口／迁移同步、针对性测试和自查。不能把当前功能正常使用所必需的处理留到后面，再称本项完成。
4. 用户复查发现的问题在当前小阶段内修正并重新交付。复查通过后更新状态；“继续下一阶段”可同时表示接受当前交付并启动下一项。
5. 每项形成可独立审查的改动。提交和推送按当次用户指令执行，不因之前提交过文档而默认自动提交后续代码。
6. 如果实施前发现一项仍过大，先在本计划内拆成更小的编号并说明范围；不在实现途中悄悄扩大到相邻功能。

本计划只拆分 §3.2。三周期分析与建议、实际账本与模拟、策略复盘仍由 §3.3–§3.5 分别设计和开发；§3.6 的完整启动器与运行管理也不并入本轮。

### 1.2 状态定义

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚未实施，可以先检查前置条件。 |
| 进行中 | 正在完成本项实现与验证。 |
| 待复查 | 实现、自查及本项必要验证完成，等待用户复查。 |
| 待修正 | 用户复查提出问题，留在本项修复。 |
| 已通过 | 用户已接受交付，可以进入依赖本项的后续小阶段。 |
| 受阻 | 有明确外部缺口，记录原因、影响和已完成部分，不视为通过。 |

下面小阶段表是实施状态的唯一记录位置；大阶段只有在所属小阶段全部通过后才算完成。文档核查、联网接口验证、代码实现和用户复查分别记录，不能互相代替。

### 1.3 每次交付给用户的内容

每个小阶段完成后，在对话回复中提供：本项编号与实现结果；主要修改文件及阅读顺序；接口或数据库结构变化；已执行验证及结果；最短人工复查步骤和预期表现；已知限制及未完成项。不另建开发过程或阶段交付记录文档。涉及错误恢复、精度或历史数据的代码，应指出对应测试案例，便于对照阅读。

涉及界面的阶段提供可打开的页面与操作路径；纯存储、适配器或后台阶段提供可重复的样本和运行说明，不要求用户只能通过 UI 检查。复查步骤必须基于本次实际实现，不能提前编造不存在的运行命令。

- D1.5 建立真实任务认领与持久化，D2.5 补齐取消、重试和异常恢复，不把任务先实现为前端计时器。
- D1.8 在首次真实目录页面开放前完成真实／演示隔离；D5 进行全流程复验。
- D5 汇总并检验跨模块行为。各小阶段的必要测试随实现完成，不集中拖到最后。

## 3. D0：数据来源验证

本阶段先核实来源，不建设正式业务数据库或改写页面。交付主要位于探针脚本、测试样本、依赖配置和来源验证记录。

| 小阶段 | 状态 | 实施与交付 | 复查重点与通过条件 |
| --- | --- | --- | --- |
| D0.1 探针环境与样本清单 | 已通过 | 建立最小 Python 环境及可重复运行的探针入口；按设计列出至少 16 个真实份额样本，说明各自覆盖类型、预期字段和核验依据；约定去敏与样本留存。 | 检查环境复现说明、样本身份和覆盖范围；能够执行一次最小来源请求，明确成功或失败原因；没有把前端虚构样例当真实基金。 |
| D0.2 目录、净值与场内行情验证 | 已通过 | 目录、单位／累计净值、ETF 日行情、场内净值和日历能验证首选来源的身份力；核对参数、单位、时间、分页、空结果和来源错误；备选来源仅在需要且权限可用时验证。 | 查看原始或适配器输出与规范化候选的对照；最新点、历史点和事件边界能人工核对；明确 ETF／LOF 等各自覆盖，不能用文档说明代替请求结果。 |
| D0.3 披露、关系、规则与材料验证 | 已通过 | 核验持仓范围与分母、分红拆分、申赎与费率；确认 ETF 联接关系和实际比例的取证方式，选择可用分类／指数及材料来源；完成去敏样本、失败样本和逐数据集准入结论。 | 检查公告日期缺口、占股票市值比与占净资产比、分类历史及使用条件；每项有通过、受限或不可用结论。关键缺口给出已验证的补充方式或明确阻塞，不能笼统标“全部接入成功”。 |

大阶段退出条件：来源验证记录可复现，设计文档中受实际结果影响的接口与限制已同步；下一阶段明确哪些适配能力可用。来源失败不阻止将来单独安排离线基础工作，但对应生产接入必须继续标为未通过。

## 4. D1：存储基础与基金目录

本阶段逐步建立真实数据的保存与读取链路。主要复查后端配置、存储、基金身份、任务、目录 API，以及前端基金库的数据访问层。

| 小阶段 | 状态 | 实施与交付 | 复查重点与通过条件 |
| --- | --- | --- | --- |
| D1.1 后端入口、数据库连接与迁移 | 待复查 | 扩展 D0 环境建立本机 FastAPI 入口、配置与错误响应；建立 SQLite 连接、迁移记录和临时测试数据库；检查实际 SQLite 版本及连接设置。 | 后端可本机启动；空库初始化与重复启动稳定，迁移失败不假报成功；外键、WAL、忙等待与连接生命周期有针对性验证。 |
| D1.2 公共事实版本与精度 | 未开始 | 建立来源注册、data_revision、选择／质量事件及必要元数据表；实现十进制字符串、时区、公开时间精度、自然键、重复观察与追加修订。 | 检查数值和时间字段、唯一约束、重复抓取和“改值后恢复旧值”案例；旧事实不被覆盖，金额不经浮点隐式转换。对应 DATA-06、DATA-12、DATA-14 的基础部分。 |
| D1.3 基金、份额与代码关系 | 未开始 | 建立产品、份额、证券、外部标识、别名与场内关联；支持 provisional 身份和有版本的归属修订，当前投影可以重建。 | 复查 A／C、同名、更名、前导零、历史代码、场内外关联；关系不重叠约束只检查某知识时点的选中版本，归属修订不改变旧身份事实。对应 DATA-02。 |
| D1.4 原始资料、最小快照与备份基础 | 未开始 | 实现文件哈希、同步落盘和数据库引用一致性；按明确 revision_id 清单冻结／读取最小快照，包含身份关系；通过 SQLite backup API 备份并枚举所需文件，在临时目录校验恢复。 | 检查文件与目录同步顺序、失败回滚和快照清单；已有版本更新后显式快照仍可读；备份不只复制数据库主文件。此项先支持 latest 输入冻结，完整历史选择留 D4。对应 DATA-18、DATA-19 的基础部分。 |

| D1.6 目录初始化与查询接口 | 进行中 | 将 D0 通过的目录适配器接入任务和存储；实现批量初始化、名称／代码／别名查询、类型与历史状态筛选、分页排序及身份详情。 | 数据分批发布后立即可查询；重新导入无重复，失败不清空旧目录，来源消失不直接删除基金。检查 API 与测试数据库结果一致。对应 DATA-01、DATA-02。 |
| D1.7 缺失基金解析与确认补录 | 未开始 | 实现代码解析任务、候选详情、歧义处理、候选确认和身份幂等入库；明确后续资料待补齐状态。 | 查不到、来源失败、已存在、身份冲突分别返回；候选确认前不误合并，重复确认不重复创建；尚未实现的数据补齐不能假报完成。对应 DATA-03。 |

大阶段退出条件：用户能在已有界面浏览和补录真实基金目录，且可沿“页面 → 接口 → 身份版本 → 来源资料”复查。净值、行情和持仓尚未接通的区块显示实际进度。

## 5. D2：净值、行情与更新

本阶段先分别建立真实序列，再接入更新与图表。主要复查序列适配器、仓储、日历、更新任务及基金详情图表。

大阶段退出条件：可以查看真实净值／行情并自主触发更新，页面如实显示已有数据、缺口与任务结果；分红及交易资料可查，实际核算仍由 §3.4 后续实现。

## 6. D3：披露、板块与规则资料

本阶段建立“持仓披露 → 投资内容 → 板块关联”的数据链路。暴露计算必须使用 D1.4 的不可变输入快照，不等待 D4 再补引用。

| 小阶段 | 状态 | 实施与交付 | 复查重点与通过条件 |
| --- | --- | --- | --- |
| D3.1 披露报告与直接持仓 | 未开始 | 实现报告批次、范围、报告期、公开时间、原文件引用与持仓明细；支持未识别证券，验证不同份额共享组合的依据。 | 整份报告原子发布；前十大不冒充全仓，不同权重分母不直接相加；来源缺失公告时刻时保留真实精度。对应 DATA-08、DATA-10、DATA-11、DATA-16。 |
