## 1. 本阶段目标与边界

### 1.1 交付结果

完成本阶段后，用户无需录入持仓，就能搜索预先收录的基金、辨认份额、查看真实净值或交易行情、查看有出处的披露持仓与板块归属，并了解缺失和过期情况。已有数据在断网、刷新页面和重启应用后仍可读取。

后续分析、账本、建议、模拟及复盘应能引用稳定身份和确定的数据版本，回答“使用了哪份资料、反映哪个日期、当时是否已经知道、后来是否被修订”。本阶段建设这套数据基础，不生成投资结论。

### 1.2 本稿采用的实施决定

1. 先建立较全面、可搜索的目录，再按关注对象补充详细历史，避免启动时逐只下载全部基金的全部数据。
2. AKShare 为首个待验证适配器，Tushare 为可选备选；业务代码不依赖来源字段名称，也不承诺两者能无差别互换。
3. 分别保存基金产品、份额和交易标的身份；净值与场内价格为两个数据集。
4. 数据按版本追加；当前查询可以采用更新资料，历史建议始终引用原数据快照。
5. SQLite 保存结构化事实和引用，本地文件保存取回资料及快照清单；精确数值使用十进制字符串与 Python Decimal。
6. 数据能否展示、能否支持指定分析、能否支持交易模拟分别判断。接口不提供含义模糊的“数据完整，所以可以买入”。

### 1.3 当前市场一致性切片（MC1）

时序写入统一校验正净值、正 OHLC、最高／最低关系及非负成交量和成交额；无效批次不替换旧序列。`GET /api/funds/{code}/series?kind=price|nav` 显式选择数据集，省略时兼容价格优先。详情的 `series_options` 列出已存储数据集；这不表示场内基金的净值适配器已自动补齐。

迁移 `011_relation_verification.sql` 追加基金关系核验历史，不修改旧迁移校验和、不删除已有关系或行情。成功核验 B 后，原 A 只保留为历史证据；失败／未解析唯一标的不删除历史，但暂不开放当前关联；无新核验且有多条旧跟踪关系时全部待核验。核验时间不是业务生效时间，`effective_from`／`effective_to` 保持未知，不能用于严格历史回测。`relation_status` 与来源、证据、核验时间在详情、研究和板块列表共同消费。

刷新分基金序列和关联指数执行。部分成功返回 `refresh.status=partial` 与逐项结果及已提交数据；全部无可发布结果返回 502，`error.details` 包含逐项 `refresh` 及核验后的 `current` 详情；失败检查已落库时，页面必须同步关系状态，不能继续把旧关系显示为当前已核验。网络请求不放入长写事务。当前仍不是跨全部数据集的不可变快照，正式研究继续依赖 D1／D4。

`GET /api/sectors/{code}/series` 必须提供 `source_id`、`universe_type`，可选 `start`／`end`；身份不符返回 404，不按名称回退。响应单列实际 `history_source_id`／`history_source_code`；跨源行情标记 `proxy_not_equivalent`，只作参考，不证明成分、权重或编制方法等价。

行业快照的目标数随范围更新；全部行业不沿用百板块数量上限。零个可核对行情身份属于采集失败，保留旧快照。实现状态和实际验证仅见投资分析计划 MC1，不在本节重复记进度。

### 1.4 当前网页目录、行业更新与详情契约（MW1）

MW1 历史切片复用现有目录、行业、基金行情和关系存储，当时不新增迁移。当前在此基础上新增迁移 012，实际增量见 §1.5；旧迁移校验和不变，仍不称完整任务系统。

| 接口 | 当前契约 |
| --- | --- |
| `GET /api/funds?q=&page=&page_size=&codes=` | 保留原分页参数兼容性；网页请求每页 6／8。可选 `codes` 为最多 60 个逗号分隔的六位 ASCII 数字代码，按去重后的传入顺序分页；不与非空 q 合用。显式空 codes 选择零条，不退回全目录；跳过未收录代码。返回 `selection_mode=codes`，前端拒绝忽略该参数的旧后端。名称检索中的 `%`、`_`、反斜杠按字面量处理，不扩大为 SQL 通配查询。总数、可见条目及关联在同一个读取事务内取得。 |
| 目录 `items[].related_sectors` | 批量查询本页基金的全部关系核验记录；只为唯一当前已核验关系返回一个目标，字段为代码、名称、行情来源、`universe_type=tracked_index`、关系来源、证据 URL 与带时区核验时间。`relation_status` 为 `linked/withheld/missing`，其他情况返回空目标和原因；不逐卡请求全量日线，不按名称补关系。 |
| `GET /api/sectors/{code}?source_id=&universe_type=` | 精确定位现有研究对象，返回 `item/generated_at/method_version`；对象非唯一或不存在返回 404，参数缺失／非法由 API 拒绝；与真实日线接口采用同一身份条件。未采集 `updated_at=null` 可以展示缺项。 |
| `POST /api/funds/catalog/refresh` | 经现有来源注册表核验后，复用目录 CLI 的同一获取／校验／导入函数，更新基金份额身份；不下载全库净值。 |
| `POST /api/sectors/refresh` | 复用 `refresh_sector_heat(..., industry_only=True)`，采集行业目录、日线及成分，随后在同一次请求、同一目标互斥范围内计算评估，返回 `refresh/evaluation/api_contract`；不更新人工经营／估值配置和既有参考指数。 |
| `GET /health` | 增加 `api_contract=market-workbench-v2` 和浏览代码选择／采集后评估能力；开发服务复用前核对协议，不能仅凭 status=ok 复用旧后端。 |

POST 的 `refresh` 含目标、起止时间、`success/partial/failed`、说明及对应数量；行业 POST 另外返回本次 `evaluation`，计算失败返回 500／`market_evaluation_failed`，不能只凭采集成功判断评估成功。行业结果分列日线／成分成功和失败数、条目原因、榜单日期，且 `manual_evidence_refreshed=false`。计数保留冻结的纳入目标 `requested_count`，不缩小到实际返回条数冒充完整；分列 `catalog_count` 和身份未纳入数，纳入子集成功不代表市场全部行业。无有效日线不是成功；部分来源成功时可发布已有提交，但不宣称整个行业池最新。

本机单进程 API 按规范化数据库路径与采集目标互斥，重复请求返回 409；工作进程分别限制目录 90 秒、行业 600 秒，防止上游库忽略 HTTP 超时后无限占用。进程无法启动返回 503，超时返回 504，采集／协议失败返回 502；接口不向客户端暴露进程环境或完整内部日志。网络请求在短写事务以外执行，入库仍沿用已有校验和提交边界。超时可能发生在某个提交之后，因此页面必须重读数据库核对，不能承诺全量回滚。行业采集、超时或协议失败写入整榜失败标识，旧行保留但不参与新排名；计算阶段仍占有互斥锁。这是 MW1 原有进程内保证；当前数据库级互斥及另存研究快照的增量见 §1.5。

关闭浏览器请求不等于服务端取消任务。当前网页批量入口及行业 CLI 使用 §1.5 的数据库目标互斥；其他未接入的导入脚本不得并行写同一目标。自动租约、分片取消和断点恢复尚未实现。原 MW1 状态保留为历史记录；新增数据能力状态在本模块计划 D1—D4 的对应行维护。

### 1.5 时点研究数据基础（当前实现，基于 main@fdbb146）

本节描述已提供源码和验证入口的后台切片，不替代后文完整设计的验收条件。应用只追加 `012_research_pipeline.sql`；现有基金／行业投影继续服务旧页面，新研究消费专用版本表，不能把当前投影当历史事实。实际检查统一见投资分析计划 §10；基金数据计划对应 D 行保留全量目标及缺口。

#### 1.5.1 日历、采集审计和失败边界

`config/exchange-calendar.json` 保存沪深交易所 **2025、2026** 年休市区间及来源；`backend/core/trading_calendar.py` 统一使用上海时区，周末补班不当交易日，未知年份拒绝推算。来源依据为[上交所2025休市通知](https://www.sse.com.cn/disclosure/announcement/general/c/c_20241223_10767108.shtml)、[深交所2025休市通知](https://investor.szse.cn/disclosure/notice/general/t20241223_611283.html)、[上交所2026休市通知](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)、[深交所2026休市通知](https://investor.szse.cn/disclosure/notice/general/t20251222_618087.html)。新增年份必须核对官方安排、更新日历版本并复验；当前不声称支持所有历史交易日。

16:00 是本项目保守的日线完成检查时间，**不是交易所收盘时间，也不是基金净值公布时刻**。当日日线在此之前不进入评估。行情采集及研究都检查交易日、重复／内部缺日和截止日期；各来源共同漏掉同一个交易日也能识别。过旧行情可保留供核对，但不足最新完整日期的研究窗口不得继续排名。停牌的业务确认仍需独立来源，不能把所有缺日命名为停牌。

`http_transport.py` 对行业 GET 采用有限重试：默认最多3次，单次总预算有上界；408／429／指定5xx及网络错误可重试，404及已取得响应后的解析、身份、空结果和结构错误不作为暂时网络错误重试。尊重 Retry-After；剩余预算不够时失败，而非提前再次请求。单响应最多10MiB。DNS／底层库阻塞仍由原目录90秒、行业600秒工作进程总上限兜底，不承诺每个系统调用严格受 socket 超时控制。

`collection_run` 记录目标、状态、时间和结果，唯一活跃目标约束覆盖同一数据库内已接入的网页 API 与行业 CLI；`collection_attempt` 记录每次请求与失败。HTTP200 的完整响应在大小限制内按字节归档并关联哈希；HTTP200仅表示取回响应，不表示解析或研究准入成功。运行状态和尝试跨服务重启可查，原始响应不混入普通任务列表。超时可能已有局部提交，旧资料和失败状态必须同时保留。

这不是完整后台队列：没有自动续租、调度、分片 checkpoint 或自动恢复。进程被强制终止可能留下 running；必须确认旧服务和所有工作子进程均停止，再用 CLI 的 `recover-collection --run-id … --confirm-workers-stopped` 记录 interrupted。不得仅凭 PID、超时或重启自行解锁，避免旧进程继续写入。未接入的目录／单基金旧脚本不因本切片自动具备该保证。

#### 1.5.2 追加事实、原文与可知时点

新增 `data_revision`、`data_observation`、`data_quality_event` 与 `numeric_fact`／`series_fact`／`research_fund_profile` 三类有字段约束的事实。数值以有限 Decimal 字符串往返，不通过 float 保存；同批重复自然键整体拒绝。同值重取只增加观察，A→B→A 会产生第三个修订，旧版本不更新或删除。业务日期、有效区间、公开时间／精度、首次采集、提交和解析器版本分别保留；服务端生成系统时间，调用方不能传入首次可知时间。

只有同时满足业务有效期、公开时间边界、首次获得、提交以及截至该时点的质量事件，事实才可进入 `system_as_of` 快照。公开精确到日时保守按该来源时区**次日00:00**进入；未知公开时刻不能通过伪造时间补齐。事实事务完成后另行发布可用质量事件，避免未提交数据被提前选择；中途崩溃的未发布事实不视为已可用。时钟倒退拒绝继续追加观察。最新修订被隔离时，不悄悄退回旧版当作当前可用；相同自然键的跨源冲突保留为缺口，不任意挑源。

原始资料保存到有大小限制的 `raw_asset` BLOB，记录 URL、媒体类型、真实字节与哈希。**这是对 §1.2 文件布局的有限实现偏差**：当前小批次原文及快照清单与 SQLite 一起备份，避免先形成未验证的数据库／文件双写协议；大型文件、许可受限全文、长期归档和全量资料仍需 D1.4／D5 继续验收。原始资料只按来源允许用途存储，不将公开访问理解为可任意再分发。

本地导入接受真实原文件及规范化事实，但 `semantic_status=verified` 表示导入者已按资料复核的声明，**程序不会仅凭该标签自动证明原文真实或字段语义正确**。必须核对身份、单位、范围、日期和原文，不能从测试夹具、模型记忆或候选字段映射补生产事实。经营背景与指数成分盈利不同；旧人工快照保留 background，未核对估值字段与缺业务日期的数值不能升级。

#### 1.5.3 固定输入与旧数据迁入

`data_snapshot`／`snapshot_item` 固定具体版本、作用域、质量排除、来源冲突、日历全文及哈希；读取旧快照不查询新投影。对象精确到 `tracked_index:<source_id>:<code>`、`hot_board:<source_id>:<code>` 或 `fund:<namespace>:<code>`，名称不能替代身份。只开放 `system_as_of`；没有真实旧版原文与当时公开证据，不开放 `public_as_of` 重建。

`research_inputs.capture_current_inputs` 在单次 SQLite 读事务取得现有投影，再按本次首次获知时间归档。迁入的原始载体明确标为本地投影，不冒充当时的上游原始响应；旧 updated_at 不用作新版本 first_seen。旧价量／单位净值可以迁入，累计净值不能自动成为总收益，基金关系不能自动补成费率、交易状态或持仓证据。旧经营配置只有背景意义；估值缺日期和语义问题继续返回缺口。再次捕获不会改变此前快照。

行业 POST 在采集后、同目标互斥范围内，保留旧 `evaluation` 并另存固定研究，返回 `collection_run_id` 及 `research.snapshot_id/run_id/status`。固定研究失败独立标为 failed，不能仅凭行情更新成功称研究已完成；`manual_evidence_refreshed=false` 仍成立。新接口在 `/api/research`，不是尚未实现的 `/api/v1`，旧网页尚无固定快照／试验管理界面。

备份已在隔离库完成恢复读取和不覆盖检查；正式运行目录的停服务替换、失败回退、大体量性能及外部资料成套恢复仍留 D5.2，不能据此宣布完整恢复验收通过。源库升级前仍须先用旧版本支持的 SQLite 一致备份方式备份；当前 backup 命令会先执行正常迁移，不把它误作“升级前不触及源库”的工具。

### 1.6 当前成分报表与估值观察（基于 main@8483c4d）

新增迁移013保存 `sector_fundamental_observation`，按来源／板块身份追加采集状态与内容哈希，禁止修改或删除旧观察。原始字节复用 `raw_asset`，不把测试夹具、抓取时间或行业名称推测写成市场事实。SQLite 的 WAL 初始化只针对 BUSY／LOCKED 做受原忙等待上限约束的重试；其他错误原样抛出。

`sector_financials` 消费本轮核验的当前东方财富成分，批量请求收入／现金流表及带交易日的估值表，保留完整分页总数、字段／报告期／公告时点校验、预算和失败原因。首个范围为已支持的沪深 A 股，未支持市场保留在分母。报表为最新已结束两期与各自去年同期，不回退到较好看的旧完整报告期。公开到日的资料次日才可用，缺公告日期不能以采集时间补齐。

收入、归母利润按同一公司集合的金额合计计算同比；现金流另列当期／基期金额和变化。基期非正则不算增长率，不把累计报表叫作独立单季。覆盖不齐时列逐公司缺项，不能删除失败对象后声称全量。来源为公开数据转录，并非逐份审计的发行人原报告；母子公司、关联交易及跨源行情代理的口径限制不消失。

PE 使用同一业务日，统计正 PE 中位数、正值／非正值／缺失数量，不用无日期市值倒算、不称官方指数 PE。估值历史按成分指纹、正 PE 样本及业务日去重，只累积实际系统观察；成分变化／失败／过期阻止旧结果被当作当前成功。同一板块新一轮先记录 collecting，最终追加完成／部分／失败状态；中断不会自动转成成功。

当前页面与固定研究共享 `read_manifest` 的可知选择；快照版本升级为 `system-snapshot-v2`，内嵌具体 `sector_fundamentals` 观察及其历史，不在复算时重查当前表。今天采集不进入昨天快照，后续修订不改旧运行。现有网页响应增加 `item.fundamentals`，原字段保留兼容；参考指数只用已经入库的同范围时点事实，不按名称套行业样本。真实源连续成功、完整行业覆盖与生产恢复仍未验收。

## 2. 基金库范围与身份

### 2.1 收录与分析范围

目录优先导入来源可提供的境内公募基金及场内基金身份，按份额建立可搜索条目。股票型、混合型、A 股相关指数基金、ETF、ETF 联接及相关 LOF 是本项目优先补齐的对象。

“目录收录”和“A 股分析范围”分开：目录可以保留债券、货币、跨境、REITs 等来源返回的身份，但首版不因收录就宣称支持其收益口径或分析。混合、跨境等情况依据投资范围、跟踪标的及披露资料标记 included／excluded／unknown，并保存判断依据与规则版本；不能只按名称猜测。

首版暂不做货币基金万份收益／七日年化核算、跨币种收益换算、复杂衍生品穿透和私募基金分析。此类对象仍可保留身份及缺失说明。境内基金持有的港股等证券可以保存，但不能强制映射成 A 股行业。

覆盖率以“本次来源目录成功解析的份额数／来源返回的有效份额数”和分类型统计报告，不声称覆盖市场全部基金。目录中消失的代码先记为待核实，不直接删除或认定清盘；历史基金保留名称、状态变更和旧代码，并可主动筛选。

### 2.2 身份模型

| 对象 | 稳定标识与关键字段 | 使用规则 |
| --- | --- | --- |
| 基金产品 fund_product | product_id、名称版本、管理人、投资类型、成立／终止资料。 | 表示基金组合层级；同一产品不同份额可关联，但必须有来源证据。 |
| 基金份额 fund_share | share_id、product_id、份额标签、币种、运作方式、状态。 | A／C 等份额分别保存净值、费用和状态；后续账本、推荐主要引用 share_id。 |
| 证券／指数 instrument | instrument_id、kind、market、currency。 | 表示股票、ETF／LOF 场内标的或明确的市场指数；行情引用 instrument_id。 |
| 场内关联 fund_listing | share_id、instrument_id、有效区间、证据版本。 | 将具体份额与场内交易标的关联；同一份额可以有净值和交易价格。 |
| 外部标识 external_identifier | namespace、code、market、对象引用、有效区间、证据版本。 | 来源代码、交易所代码和注册代码分命名空间；六位代码存字符串，保留前导零。 |
| 名称与别名 identity_alias | 对象引用、名称、有效区间、来源版本。 | 更名保留旧名搜索；同名不合并，基金转换或合并不直接复用旧身份。 |

内部 ID 使用不含业务含义的 UUID 字符串。基金代码仅作外部标识，不能作为所有业务表的主键。在某个知识时点下选中的有效代码映射必须唯一、业务有效区间不得重叠，跨来源冲突进入待核验队列；同一业务区间的历史修订可以共存，不能对所有修订行施加不重叠约束。无法确认产品归属时建立独立的 provisional 产品，identity_status=unverified；之后追加归属修订，保留 share_id 和旧快照，不凭名称自动合并。产品归属写入 profile_revision，代码映射、别名与场内关联各自关联 revision_id；fund_share.product_id 等当前字段仅作可重建投影，历史查询不读取今天的归属来替代旧版本。

持仓通常在产品／组合层披露，净值和费率通常与具体份额有关。只有确认份额共享对应组合后，才能共享披露持仓；不能把 A 类净值或渠道费率直接用于 C 类。

### 2.3 搜索与缺失基金补录

目录搜索支持代码精确匹配、名称／别名包含查询、基金类型、板块、历史状态、数据能力筛选及分页。排序固定追加 share_id 作为并列项顺序；精确代码匹配优先。默认搜索本地目录，不逐次请求外部网站。

补录流程：输入代码 → 格式校验 → 查询本地映射 → 后台查询候选身份 → 页面展示名称、份额、币种、市场与来源 → 用户选择候选 → 幂等创建身份并排队补齐数据。六位数字校验仅适用于当前基金代码输入框，不作为所有证券代码的统一校验。

已存在的对象返回原 share_id；不确定的候选不直接作为已核验基金加入正式分析。上游未返回记录、网络失败、来源不支持、身份冲突分别报告。自动初始化的明确目录条目无需逐项人工确认；只有用户补录时的候选歧义需要选择。

### 3.2 接入探针与准入

D0 核验结论以 `config/data-source-registry.json` 作为跨阶段机器可读入口，设计正文用于解释原因，`runtime/probes/` 仅用于本机复查。后续采集按 dataset 和 allowed_uses 选择来源：automatic 来源可以进入无人值守采集；discovery_only 只能产生待确认候选；authoritative_evidence 用于确认正式事实；rejected 与 not_verified 不调用。注册表由 `scripts/data_source_registry.py` 在启动和测试时校验，来源状态、用途或优先级变化必须作为受审查的配置修改提交。每次采集还要把注册表的 `policy_version` 和实际命中的来源 `id` 写入 data_revision，使历史数据能还原当时采用的 D0 准入规则。

在大批量采集前建立至少 16 个真实份额的固定验证清单，覆盖股票／混合、同产品 A／C、宽基与行业 ETF、ETF 联接、LOF、新成立、历史基金、分红／拆分和缺失数据；一个样本可覆盖多个类别。代码与核验日期记录在测试资料中，本设计不借用前端虚构名称作为真实身份。

每个来源／数据集提交：请求及版本、去敏响应样本、字段映射、单位换算、最早／最新日期、分页限制、缺失率、错误类型、调用限制、使用条件链接、人工交叉核对结论。至少核对最新一条、一个历史点和一个事件边界；交易价及净值分别与原始发布页面核对。涉及未知能力的接口先标记 unsupported 或 unverified，不能返回空数组并表示成功。

探针通过标准：样本身份一致；日期和单位可解释；重复取回不重复入库；断网／空结果／字段改变有明确处理；公开时间或历史版本不可得时能按 §6 降级。生产采集在探针通过后启用，CI 使用获准保留的离线样本，联网探针单独运行。

AKShare 1.18.94 的接入约束：`fund_name_em` 是当前目录，缺项不代表没有历史净值；其名称与类型标签不能直接确定产品归属、币种或场内外关系。`fund_open_fund_info_em` 的单位／累计净值返回来源全量历史，日期窗口需本地筛选；`fund_etf_fund_info_em` 内部按 20 条分页，空区间可能抛出拼接错误，应保留为来源失败。字段中的净值日期不是公开时点；数字已被转换为数值类型，不能声称恢复了来源原始小数精度。

拆分登记日的净值可能已经按新份额调整，交易除权日却是下一交易日；累计净值也可能采用调整后的序列口径，不能强制“累计净值大于单位净值”，或仅凭两天净值之比计算收益。事件与历史修订仍按 §4、§6 单独处理。新浪交易日历只作为境内交易所参考，保留适配器补入 1992-05-04 的事实及实际覆盖边界，不能推定境外基金开放日或覆盖结束后的交易日。

ETF 历史日行情的来源顺序为新浪、腾讯、BaoStock、东方财富；LOF 为新浪、腾讯、东方财富。新浪接口的实际成交量单位为份，与接口文档标注的“手”不一致；成交额为元且可能缺失。腾讯原始成交量为手、成交额为万元，保留原始字符串后用 Decimal 换算，并注明来源舍入。腾讯每个请求最多 640 条，结束日期决定向前返回的范围，开始日期可能被忽略；按年切分、本地筛选、检查截断。BaoStock 只用于已验证的 ETF 近期窗口，缺失长历史时标为截断并继续下一来源。当前获取的日期范围仍须保留，不能保证任意基金、任意历史区间都覆盖。

来源自动切换处理网络、超时、上游失败、空结果或无法证明完整的截断，每个来源尝试一次；身份、字段或行情质量异常立即停止。每份结果使用单一来源，不拼接、不平均；记录实际来源和失败尝试。不复权口径需以分红、拆分边界持续核验，公开时间与历史修订仍按 §6 降级。Tushare 备选因无已配置可用权限而保持未验证。[新浪基金历史接口](https://akshare.akfamily.xyz/data/fund/fund_public.html)、[腾讯历史接口参考](https://akshare.akfamily.xyz/data/stock/stock.html)。

### 3.3 适配器契约与来源切换

适配器按数据能力提供 catalog、profile、nav、bars、holdings、events、rules、calendar、taxonomy、materials 方法，返回规范化候选记录、来源请求信息、时间精度、原始资料引用及缺失原因。未实现的方法显式返回 unsupported。分页、请求超时、限流、列名变化和上游单位转换留在适配层；业务层不直接调用 AKShare 函数。

来源注册表保存 provider_id、上游发布者、adapter_version、数据集能力、条款链接、核验日期、调用间隔、授权状态和是否允许保存原文／发送 AI。开源客户端的许可不能代替底层数据授权；无法确认原文保存范围时只保留允许的元数据和链接，并如实降低可复算性。

同一事实多来源不求平均、不直接覆盖。按数据集保存 source_policy_version：优先级、单位／币种／口径要求、容差及降级规则。备选来源只有通过身份与口径校验才可被选用；冲突保留双方记录和选择原因。切换后的曲线显示来源分段；无法证明兼容时返回独立序列或缺口，不静默拼接。

| nav_revision | share_id、nav_date、nav_kind、value、currency、valuation_status。 | nav_kind 区分 unit／accumulated；估值另标 estimated，不替代 confirmed 净值。 |
| bar_revision | instrument_id、trade_date、frequency、open、high、low、close、volume、turnover、currency、adjustment。 | 本阶段日线，原始不复权；成交量换算为明确单位，缺失为 null。 |
| calendar_revision | market、date、is_open、session 信息、来源。 | 交易所交易日与基金开放／估值日历分别表达；日历不可用时不靠“周一至周五”伪造。 |
| trading_status_revision | share_id／instrument_id、业务类型、状态、额度、有效区间、渠道。 | 停牌与暂停申购／赎回分开；没有限制资料表示 unknown。 |
| corporate_action_revision | share_id／instrument_id、event_type、原始事件 ID、各业务日期、现金每份、拆分比例、币种。 | 分红和拆分分别建事件，名称相似或同日不能简单去重；修订关联原事件。 |

净值是估值资料，场内价格是交易资料。基金列表的 latest_value 必须携带 value_kind、value_date、currency、valuation_status 和来源；详情允许在可用时切换“交易价格／单位净值”，不再使用一个 nav 字段装两种数值。

日行情校验 high ≥ max(open, close)、low ≤ min(open, close)、high ≥ low；数量非负，价格符合标的状态及来源口径。空值、重复日期或异常振幅先分级标记：明显单位／结构错误阻止发布；大幅波动与疑似事件进入待核验，不能自动删除真实极端走势。累计净值不要求单调增加。

以日期键关联不同序列，API 返回实际日期点和缺口原因。非交易日无需补点；应有但缺失的交易日返回 missing，已证实停牌返回 suspended；净值尚未公布与抓取失败分别标识。UI 可绘制断点，但不能用 0、线性插值或前值制造已确认行情。以后 §3.4 如需前值估值，必须单独输出估算结果和所用日期。

“当日涨跌幅”按同一口径的相邻有效值计算，返回 previous_date 与 change_basis；如果跨越应有数据缺口，则只能标为区间变动或 null。列表按涨跌幅排序时分清最新值日期和数据种类，不把不同日期的变动描述为同一日排名。

### 4.2 分红、拆分与复权

原始单位净值、累计净值、未复权价格、来源提供的复权序列分别存储，不能相互覆盖。默认图表使用单位净值或不复权价格并标出口径；累计净值曲线不命名为“含分红再投资收益率”。

adjustment 取 none／forward／backward／total_return，并另存 factor_set_id、基准日、来源／算法版本和输入快照。首批必须交付 none；其他选项只在因子和计算验证通过后开放。展示用复权价格不能作为真实申赎确认价或模拟成交价，历史复权因子也必须经过时点筛选。

分红保存公告、权益登记、除息、现金支付和再投资确认日期中实际可得的部分；缺失日期不互相代填。将“每十份派 x 元”等转换为 cash_per_unit 时保留原单位和原值。拆分明确 new_units_per_old_unit，防止正反比例颠倒。

D0.3 核验后，东方财富年度分红／拆分表只作为事件发现和结构化交叉核对；管理人或交易所正式公告是金额单位、拆分方向、除权日和发布时间的主证据。510050 的 2025 年分红样本验证“每十份 0.80 元”可换算为每份 0.08 元；515050、513660 的 2026 年拆分分别由安排及结果公告确认 new_units_per_old_unit 为 3、2。新浪累计分红只能核对累计值，不能作为独立事件来源。

后续收益计算只能明确选择“原始价格／净值 + 现金流及份额事件”或已定义的总回报序列；不能使用已含分红的收益数据又重复记一次分红。事件缺失时，数据服务要能返回阻止精确收益或模拟的原因。

### 4.3 费率、交易规则与人工补充

rule_set_revision 保存 share_id、channel、operation、currency、effective_from／to、公开时间、来源文件、确认状态、规则结构版本；rule_tier 保存金额或持有天数上下界、是否包含端点、rate、fixed_fee、最低／最高费用及原文。计费方式、持有期起算、自然日／交易日、申请截止时间、确认／到账规则、金额／份额舍入分别保存为字段，未知用 null。

申购费、赎回费、管理费、托管费、销售服务费及渠道费用分类记录。已经计入净值的持续费用标记 included_in_nav，供 §3.4 避免再次扣费；不是见到“费率”就执行扣款。用户示例中的 7 天／30 天档位只作边界测试，不能写成基金通用费率。

D0.3 实测 fund_fee_em 可以发现当前费率档位、交易状态、确认日和运作费用，但来源不提供有效期或历史版本；“天天基金优惠费率”必须绑定 eastmoney 销售渠道，不能覆盖基金合同原费率。009314 的赎回档位可作为 7／30 天边界测试样本，正式计费前仍需以当期官方产品资料确认端点、持有期定义及生效日期。

人工规则以 user_provided 来源独立追加，保存录入时间、适用渠道、依据和确认说明；它不覆盖公开来源。未来计算必须固定选择的 rule_set_revision_id，并说明选择依据；规则冲突、区间重叠或关键日期不明时返回待核对。具体计费公式与最终选择优先级由 §3.4 定义。

## 5. 披露持仓、ETF 联接与板块归属

### 5.1 披露批次

holding_report_revision 表示一个完整披露批次，包含 product_id、report_period_end、report_type、scope、denominator、published_at、来源文件及解析版本。scope 区分 top_n／full_disclosed／asset_allocation／unknown；“报告披露完整”不意味着实时持仓完整。

holding_item 引用报告 revision_id，保存 security_id、原始名称／代码、asset_type、quantity、market_value、weight、weight_denominator、rank。无法识别证券时保留原行与 unresolved 标记，不把整份报告丢弃。报告和明细整批验证、整批发布，不能把半份报告展示为已完成。

权重分母区分 fund_net_assets／stock_market_value／total_assets／unknown。只有同一分母，或具有同批次可靠换算依据的权重，才能相加。披露股票权重为 60% 不等于其余 40% 是现金；应称未展开部分，除非资产配置资料进一步解释。

D0.3 实测 fund_portfolio_hold_em 可条件准入为“东方财富披露股票持仓快照”：百分比以基金净资产为分母，万股和万元分别换算为股和元；接口按年度一次返回多个季度，每期最多 100 只且没有公告时间。达到 100 只表示命中来源上限，少于 100 只也不自动表示完整，因此 scope 和 completeness 保持 unknown，published_at 保持 null。000051 的直接股票权重合计远低于 100%，验证了联接基金不能对返回持仓重新归一化。

### 5.2 ETF 联接穿透

fund_relation_revision 保存 feeder → target ETF 的关系、有效区间和证据；该关系仅证明投资目标。实际配置比例取自对应 holding_report，不能默认 100%，也不能把合同要求的比例当作实际持仓。

关系发现不能只依赖基金名称或跟踪指数。首批已用管理人资料核对 000051／005658 → 510330、013304 → 159781、008396 → 159968、050025 → 513500；这些关系仍需随合同修订保存有效期。合同中的“目标 ETF 不低于基金净资产 90%”是投资限制，报告期实际比例必须另从定期报告的基金投资明细取得。

穿透以联接基金直接披露为根：保留直接股票；目标 ETF 持仓行转换为对应股票的间接暴露；合并相同证券的直接与间接权重，同时保留每条路径。组合层面的 ETF 权重与穿透后的股票不能在同一合计里计算两次。

当两层权重均以各自基金净资产为分母，间接权重为：

~~~text
联接基金对股票 S 的间接权重
  = 联接基金投资目标 ETF 的权重 × 目标 ETF 对股票 S 的权重
股票 S 合并权重 = 直接权重 + 各有效穿透路径的间接权重
~~~

例如联接配置 ETF 为 90%，目标 ETF 某股票为 10%，联接另直接持有该股票 2%，则该股票暴露为 11%，路径分别为直接 2% 和间接 9%。这是口径示例，不是真实基金数据。

首次实现最多穿透一层目标 ETF；环路、多层基金投资、目标缺失、分母不兼容及比例未知均保留 unresolved 权重。优先使用同报告期、且在查询时点可用的两层报告；没有同报告期资料时，允许另提供“跨期参考估计”，显示两层日期，默认不授予严格历史分析能力。

### 5.3 分类、主题与未知部分

sector 保存 sector_id、taxonomy_id、分类层级和父节点；taxonomy_revision 保存提供方、版本和适用时间；membership_revision 保存证券到分类的映射及依据。基金的板块暴露由持仓权重与映射计算，输出 exposure_result，引用全部输入 revision_id 和 algorithm_version。

行业与主题分开。只有选定分类体系同一层级的互斥行业可以用于分布合计；跨层级不能相加。主题允许同一证券属于多个主题，应使用可重叠列表或条形图，不能生成加总为 100% 的主题饼图。

结果分别返回已分类股票、未分类股票、已知非股票资产、未披露／未穿透部分和分母说明。只有非杠杆、权重分母一致、数据自洽时才计算 1 − 已知权重作为剩余；出现负数、净敞口或杠杆时报告不适用，不能截断为零、强制归一化或伪造完整性。

例如前十大股票共占净资产 60%，其中 50% 可归属行业，则应显示“已分类 50%、已披露但未分类 10%、未展开 40%”；不得把 50% 放大为 100%。完整度、分类覆盖率和 ETF 穿透率为不同指标，并各自说明分母。

### 5.4 板块基础数据与后续分析

板块详情本阶段提供身份、定义、分类体系、可用历史成员、相关基金和暴露证据。板块走势必须关联明确的 index_instrument_id、提供方与指数编制／收益口径；不能把某基金净值乘常数作为板块指数。

没有合适指数时可以展示分类和相关基金，指数区说明缺失。板块涨跌、基金关联与板块机会分开；三周期机会、summary、risk 及评分由 §3.3 生成，本阶段不从当前静态文案生成真实分析结果。

## 6. 历史时点、修订与数据快照

### 6.1 时间语义

日期用 YYYY-MM-DD；时间戳存 UTC、带时区的 ISO 8601，页面统一转换为 Asia/Shanghai。来源日期保留 source_timezone 与时间精度；只有日期时不能编造精确发布时间。

| 字段 | 含义 | 示例用途 |
| --- | --- | --- |
| effective_date／valid_from、valid_to | 数据反映日期或业务有效区间。 | 净值日期、报告期末、分类与费率适用期；区间采用左闭右开。 |
| published_at、published_date、publication_precision | 该份资料／该次修订对外公开的时间与精度，可空。 | 报告期末不是公告时间；规则生效日不等于公开日。 |
| fetched_at | 某次请求实际取回时间。 | 网络采集记录，每次取回都保留任务／观察信息。 |
| first_seen_at | 本系统首次观察到这个版本的时间。 | 本地当时可用的保守界限，回填时不能倒填。 |
| committed_at | 版本正式发布入库时间。 | 解析延迟、隔离审核、快照可见性。 |

### 6.2 追加版本与当前选择

所有参与展示、计算或追溯的事实都带 revision_id 和共同来源字段。data_revision 保存 dataset_kind、record_key、source_id、source_revision_no、payload_hash、时间字段、raw_asset_id、parser_version、supersedes_revision_id。具体数值放对应类型表，以 revision_id 外键关联；不把所有业务事实塞进任意 JSON。

record_key 是与数值无关的规范化自然键，例如“share_id + nav_kind + nav_date”或“instrument_id + trade_date + frequency + adjustment”。同一来源再次取回与其当前版本相同的规范化内容，只增加采集观察，不增加版本；内容、有效期、公开时间证据或解析解释发生变化则追加版本。历史上曾出现过的旧值再次成为新修订，仍须新建版本，不能用全局 payload_hash 唯一约束吞掉这次变化。

原版本、原文件和已发布快照不可原地修改或删除。坏数据追加撤回／隔离事件；修订保留 supersedes 关系。当前选用关系也保存 selection_event（record_key、revision_id、选择时间、原因、source_policy_version），当前投影可更新或重建。对于来源漏返回的旧记录，除非有明确撤回证据，否则仅记录缺口，不据此删除历史事实。

### 6.3 三种读取方式

| 模式 | 选择原则 | 用途 |
| --- | --- | --- |
| latest | 已发布、当前未隔离且符合来源选择策略的版本。 | 今天的基金浏览和更新后的分析准备。 |
| system_as_of | 在 cutoff 前已 first_seen 且已 committed 的版本，使用截至当时的选择／质量事件。 | 回看本系统当时实际可用的数据。 |
| public_as_of | 该精确版本的公开时间有可信证据且不晚于 cutoff；有效期也符合目标业务日。 | 事后历史研究，必须标为重建，不冒充当时系统已运行。 |

published_at 缺失时，最早仅能保守采用 first_seen_at；只有发布日期时，保守可用界限取该来源时区的次日 00:00。能够核验准确发布时刻后可追加新版本修正时间证据。今天获取的“六月末持仓”不能自动用于六月末，今天下载的被修订历史净值也不能直接当作当年可知值。

public_as_of 必须能证明“这个修订版本”当时已公开；只有原报告日期、没有修订公开时间或历史版本证据时，仍按本次 first_seen 界限或标为不可严格重建。材料公开日期早于截止时间，并不证明后来训练的 AI 模型没有事后知识，AI 历史重建限制由 §3.3–§3.5 另行处理。

任何模式均先限定业务有效日期／区间，再筛选知识时点；不能只按 nav_date／report_period_end 过滤。历史选择的来源优先级、分类版本和质量判定也必须随快照固定。

### 6.4 数据快照与复算

data_snapshot 保存 snapshot_id、purpose、selection_mode、cutoff、业务区间、created_at、source_policy_version、quality_policy_version、manifest_hash、状态和缺失项；snapshot_item 逐项引用 data_revision。清单包含份额归属、代码映射、场内关联等解释输入所必需的关系修订，不能只冻结净值和持仓数值。衍生暴露、复权序列等另保存 algorithm_version、参数与输入快照。

快照在同一个短读事务里解析输入版本并固化清单，随后写入快照记录；若期间某版本被撤回，提交前重新检查并记录状态。外部请求不在快照事务内进行。快照内不同资料可以有不同报告日，不能用一个 data_date 遮蔽这种差异。

建议、模拟、复盘后续引用 snapshot_id，不调用 latest 来还原旧结果。重算产生新 run_id，关联旧结果、原因和新快照；旧输出继续可见。大清单可写本地文件，但数据库仍有可校验的清单哈希与修订引用。

最小验例：7 月 20 日取回 6 月 30 日持仓，7 月 21 日生成建议，8 月 1 日来源修订。7 月 21 日快照仍指向首版；latest 可以指向修订版；6 月 30 日历史查询不能看到该份报告；8 月补跑不能创建伪装在 7 月发布的新建议。

| 任务与能力 | data_job、data_job_item、data_quality_issue、dataset_coverage。 | 活跃任务去重键唯一；任务分片自然键唯一；对象＋数据集＋范围查询索引。 |
| 工程基础 | schema_migration、idempotency_record、backup_manifest。 | 迁移版本唯一；请求作用域＋幂等键唯一；备份清单及恢复校验状态。 |

用于检索的常用身份／状态字段可以保留可重建的当前投影；必须有 revision_id 指回来源事实。原始来源响应可用 JSON 文件保存，固定业务查询字段不放入无约束 JSON。SQL 全部参数化。

### 7.2 精度与序列化

SQLite REAL 和 JavaScript number 都不能承担精确记账。数据库将金额、份额、净值、价格、费用、权重和费率保存为经过校验的普通十进制 TEXT；API 使用 JSON 字符串，禁止 NaN、Infinity 和以科学计数法传递正式金额。SQLite 的二进制浮点数是近似表示，精确数值需另行设计。[SQLite 数值精度说明](https://www.sqlite.org/floatingpoint.html)。

| 数值 | 本稿建议的接入上限 | 运算与舍入 |
| --- | --- | --- |
| 金额／费用 | 最多 28 位有效数字、12 位小数，币种必填。 | 保留确认记录原值；人民币展示常用 2 位，不据此截断中间值。 |
| 份额／净值／价格 | 最多 28 位有效数字、12 位小数，保留来源精度。 | 适配器保留 source_scale；超限隔离，不默默四舍五入。 |
| 费率／权重／收益率 | 小数比例，例如 1.5% 传 "0.015"。 | 运算不先转百分数；显示时再乘 100，注明百分比或百分点。 |
| 成交量／成交额 | 股／份／手先按明确换算归一；成交额标币种。 | 能确认为整数时使用 INTEGER，否则十进制 TEXT；禁止把“万”遗漏。 |

Python Decimal 工作精度至少 40，金额核算入口只接收字符串，不从 float 反推精确值；第三方库若已转 float，应记录来源精度并按已验证规则规范化，不能宣称恢复了原始小数。精确 SQL 汇总不得把 TEXT 隐式转换 REAL；读取后用 Decimal 运算，排序也不得按字符串字典序比较数值。

图表可以在展示边界转换 number，tooltip 优先保留原字符串；这些数值不能回流成账本事实。显示舍入采用明确的展示规则，确认／费用舍入由适用交易规则决定；规则未知时不能默认所有基金均使用同一舍入方式。后续计算记录 rounding_policy_version。

### 7.3 并发、事务与幂等

SQLite 仅放本机磁盘，启用 WAL，写入采用短事务；每条连接显式启用 foreign_keys，并设置 busy_timeout。首版建议 busy_timeout=5000 ms、synchronous=FULL，具体调整须通过故障恢复验证。WAL 允许读写并行，但同时仍只有一个写者；独立任务进程串行执行并不能消除 API 与任务之间的写竞争。[SQLite WAL](https://www.sqlite.org/wal.html)、[外键启用规则](https://www.sqlite.org/foreignkeys.html)。

创建／认领任务、身份合并、选择当前版本等读后写操作使用短 BEGIN IMMEDIATE 事务；网络抓取、文件下载与长计算在事务外。锁竞争有限重试并返回可重试错误，不无限等待。进程各自管理连接，不跨进程共享连接对象。

实施时检查 Python 实际加载的 SQLite 版本，采用包含 WAL-reset 修复的版本；官方说明 3.51.3 及以后已修复，部分旧分支另有补丁。不能仅记录 Python 版本而忽略 SQLite 运行库。[SQLite WAL-reset 修复说明](https://www.sqlite.org/wal.html#walreset)。

写接口使用 Idempotency-Key，服务端记录作用域、请求哈希、状态、对象 ID 和响应。相同键同请求返回原结果，异请求返回 409；业务写入与幂等结果原子提交。任务去重另按 kind＋对象＋数据集＋规范化范围＋来源策略生成 dedupe_key，只约束活跃任务，允许结束后再次主动更新。

### 7.4 数据库与文件一致性

~~~text
runtime/
├── database/app.sqlite3
├── raw/sha256/<前两位>/<内容哈希>.<扩展名>
├── snapshots/<snapshot_id>/manifest.json
├── cache/                         可丢弃的查询或图表缓存
├── logs/                          去敏运行日志
└── backups/<backup_id>/            数据库、所需文件、manifest.json
~~~

raw_asset 标明 artifact_kind=source_response／adapter_output／document。若 AKShare 只暴露整理后的 DataFrame，保存其输出时应称适配器输出，不能宣称是原始 HTTP 响应。用于核验的文件记录来源 URL、内容类型、哈希、字节数和允许的留存范围；密钥和带令牌 URL 不进入文件名、日志或快照。

写入顺序：抓取到临时文件 → 验证并计算哈希 → 同步文件内容持久化 → 同文件系统原子重命名到不可变路径 → 同步父目录项持久化 → 短事务登记 raw_asset、版本及分片完成状态。新建的目录层级也须完成相应同步；按运行平台验证同步操作，快照清单遵循同一协议。原子重命名本身不保证断电后文件已落盘。数据库提交失败可留下未引用文件，由恢复扫描处理；任何持久化步骤失败时不能提交有效事实引用。数据库和文件并无跨介质原子事务，必须通过这一顺序与校验收敛。

### 7.5 迁移、备份和保留

迁移采用按序 SQL 文件及 schema_migration，记录版本、校验和、执行时间。API 与任务启动时检查兼容版本；只由一个维护入口迁移，迁移前停止写入并完成备份，失败保留可恢复旧副本。不在本阶段引入数据库服务器或分布式迁移系统。

备份通过 SQLite backup API 生成一致数据库副本，再从副本中的引用枚举不可变原始文件和快照清单，复制并校验哈希，最后原子发布备份 manifest。备份期间禁止清理被引用文件；新采集文件不必纳入此前数据库副本。不能在 WAL 正在使用时只复制 app.sqlite3 并称为完整备份。[SQLite Backup API](https://www.sqlite.org/backup.html)、[WAL 文件说明](https://www.sqlite.org/wal.html)。

备份清单包含 schema_version、应用／解析版本、数据库与文件哈希、创建时间和缺失项，不含 API 密钥。恢复先在临时目录验证哈希、integrity_check、foreign_key_check、引用完整性与版本兼容；成功后由 §3.6 维护流程停止 API／任务的数据库访问、关闭全部连接，再替换成套目录并重新连接，保留恢复前备份。WAL／SHM 随 SQLite 正常关闭处理；异常残留与旧数据库一并保留在旧目录，不手工单删，也不让旧连接访问新库。验证失败不能覆盖正在使用的数据，替换失败保持维护状态并恢复旧目录。

已被快照引用的事实、原始依据、规则和将来的个人记录默认长期保留；本阶段不自动删除事实版本。普通缓存可清理，日志按容量轮转，未引用临时／孤立文件经过宽限期和引用复核才可清理。许可不允许完整留存的材料保留合法元数据，并标记该结果只能追溯链接、不能完全复算。磁盘不足时暂停采集并保留已有数据，不自动删历史证据腾空间。

## 8. 初始化、增量更新与任务恢复

### 8.1 分层采集范围

| 数据层 | 初始化 | 后续更新 |
| --- | --- | --- |
| 全量身份目录 | 导入所有来源可得目录、份额映射及类型；可批量取得的最新值独立导入。 | 建议每日检查一次目录；新增、变更和疑似消失分别处理。 |
| 重点基金 | 用户打开／补录的基金，以及后续持仓、关注、候选分析引用的基金。 | 首次默认回填近 3 年可得净值／日行情、期间事件及近 3 年披露；成立不足则取实际范围。 |
| 目标与依赖 | 对应目标 ETF、已披露证券身份、选定板块／指数、交易日历。 | 按依赖补齐，缺失不阻塞无关基金；避免全市场逐证券下载全部行情。 |
| 历史研究 | 按明确对象与时间范围发起回填。 | 保存申请范围、实际范围与缺口；更长窗口由 §3.3／§3.5 按研究需要提出。 |

近 3 年是采集预算默认值，不是“足够预测未来”的承诺，也不定义短中长期分析门槛。大型全量初始化分批发布，已入库部分可搜索；界面展示真实已处理数量和失败范围。

### 8.2 更新策略

每日净值和场内日行情按各自日历与来源发布规律检查，不把当天尚未公开的数据判定为下载失败。建议本机每日晚间尝试更新，次日上午补查；这是本产品调度默认值，不是基金统一披露截止时间。具体时刻配置在 source_dataset_policy，首批探针后确定。

日序列增量默认回看最近 10 个应有数据日，发现修订追加版本；每月对重点对象核对最近 1 年。持仓每周检查最新报告及最近两个报告期，发现公告可提前更新。分类、规则、分红／拆分按各自来源频率检查，用户请求可主动刷新。重叠窗口和定期核对不能保证发现窗口外所有修订，数据状态保留 last_full_reconciled_at；正式历史研究前按所需范围复核。

断网、休眠或关机恢复后按水位与缺口补实际数据，不以错过调度次数机械重跑全部任务，不补造未发生的历史分析或建议。更新失败保留 last_success_at 和旧数据；last_attempt_at 不能被展示成数据日期。

### 8.3 持久化任务最小协议

data_job 至少保存 id、kind、request、dedupe_key、status、created_at、started_at、heartbeat_at、lease_owner、lease_generation、lease_expires_at、cancel_requested_at、checkpoint、processed_count、total_count、last_error、retryable；data_job_item 保存每个对象／数据分片的结果、完成水位和错误。

状态为 queued／running／recovering／succeeded／partial／failed／cancel_requested／cancelled，对应界面排队、执行中、等待恢复、已完成、部分完成、失败、取消中、已取消。total_count 不可知时为 null，禁止伪造百分比。succeeded 表示请求分片处理成功，不等于每只基金具备分析条件。

任务进程原子认领任务，运行租约过期后才可恢复；使用进程锁和递增 lease_generation，旧执行者在提交前必须校验认领代次，防止休眠恢复后的旧进程与新进程重复提交。网络请求配置有限超时并在事务外运行；采集结果与分片 checkpoint 在同一事务提交。

取消在分片边界生效，已完成数据保留；取消请求与最终取消为两个状态。临时网络错误按有限退避重试，认证／权限／结构变化不反复重试；部分失败只重跑失败片段。来源限流统一按来源执行，避免每只基金独立重试形成请求高峰。

## 9. 数据质量、新鲜度与能力

### 9.1 状态分层

每个对象按数据集分别返回三组状态：coverage=none／partial／complete／unknown，quality=valid／warning／quarantined，freshness=fresh／stale／unknown／not_applicable。complete 必须相对于明确请求范围或披露范围；例如“报告前十大解析完整”不等于“基金持仓完整”。

dataset_coverage 记录 requested_range、available_range、expected_count、actual_count、missing_ranges、latest_effective_date、latest_published_at、last_success_at、last_attempt_at、last_full_reconciled_at、reason_codes 和 evaluated_at。expected_count 无法确定时为 null，不能生成假覆盖率。

日数据新鲜度按“到当前时刻按来源规则应该已提供的最新日期”判断；休市日不增加欠缺交易日。披露数据同时展示报告年龄和是否已知有更新报告，不把季报当作日更资料。首次可采用“报告期末距今超过 180 个自然日”作为 UI 警示默认值，存入 quality_policy_version；它不是统一法定期限，也不自动定义分析许可。未来有效的规则不等于已经过期，生效状态另判。

### 9.2 能力契约

capabilities 按 purpose 返回 state=available／limited／unavailable／not_evaluated、所需数据集、范围、缺口、证据版本和 evaluated_at。数据服务本阶段实现以下能力查询：

| 能力 | 最低条件 | 缺失处理 |
| --- | --- | --- |
| searchable | 身份可定位，代码映射无未决冲突。 | provisional 身份可展示但标待核验。 |
| nav_chart／price_chart | 对应真实序列至少有一个有效点且口径明确。 | 一点可展示数值；不足两点说明不能形成走势；缺口可见。 |
| holdings_display | 报告范围、报告日期和分母可解释。 | 缺公开时间时仍可查看，历史用途受限。 |
| sector_exposure | 有可换算持仓、有效分类映射和输入快照。 | 部分映射返回 limited 和未知比例，不伪装全覆盖。 |
| historical_inputs | 调用方给定数据集、区间、最小样本、时点模式和允许缺口后通过评估。 | 返回具体缺项，不用固定“完整”标签代替所有算法门槛。 |
| execution_inputs | 指定份额／渠道／业务日可提供价格、事件、日历、状态和规则引用。 | 仅表示输入是否齐备，真正可成交与费用校验仍由 §3.4 判断。 |

§3.3 尚未给出算法需求时，trend_analysis、sector_analysis 等业务能力返回 not_evaluated。§3.4 尚未接入时，simulation 返回 not_evaluated；不能因规则表存在就开启实际核算。不同周期的样本要求由后续模块显式传入，本阶段不假定同一门槛适用于一周至六个月。

异常必须含可机器识别的 code 和面向用户的解释，例如 IDENTITY_CONFLICT、MISSING_PUBLICATION_TIME、HOLDINGS_PARTIAL、DENOMINATOR_UNKNOWN、STALE_NAV、SOURCE_SCHEMA_CHANGED、RULE_UNCONFIRMED。某个数据集失败不清空其他可用区块；隔离事实保留诊断及原始引用，但默认不进入有效序列。

    "generated_at": "2026-09-13T02:00:00Z",
    "snapshot_id": null,

写请求失败返回 error.code、message、field_errors、retryable、request_id。202 表示任务已持久化排队，不能显示“数据更新完成”；保存超时使用原 Idempotency-Key 查询／重试，不生成新键造成重复创建。前端按钮依据 allowed_actions 与 capabilities，不按颜色、基金名称或“完整”汉字自行推断。

后续分析服务显式提交 requirements（对象、数据集、区间、时点模式、最小样本、容许缺口），调用 evaluate_requirements 再调用 create_snapshot；计算服务只消费已固定快照。存储层不决定策略周期边界、收益公式或买卖方向，也不承担 AI 输出正确性的判定。

D0.3 对材料来源的准入顺序确定为：基金管理人、交易所和监管部门的正式公告／法律文件作为主证据；东方财富等门户的公告目录和结构化表作为发现入口与交叉核对；新闻、研报和搜索摘要不能裁决基金身份、费率、关系或公司行动。只有网页显示日期时保存 published_on，published_at 保持 null；每个站点的正文留存、附件下载和 AI 发送权限在正式接入前分别核对，不能因公开可访问就默认允许长期复制或外发。

### 12.2 可逐步验收的开发批次

逐项执行与代码复查见[分阶段开发与复查计划](fund-data-storage-plan.md)：以下 6 个大阶段已拆为 31 个小阶段，每项分别定义实施范围、复查重点、通过条件和状态。默认一次执行一个小阶段，完成实现与验证后交由用户复查。

| --- | --- | --- |

版本字段从 D1 开始建立，不能先覆盖写入、到 D4 再补历史。D1 同时建立按明确版本清单冻结的最小快照，供 D3 暴露计算引用；完整历史时点选择与要求评估在 D4 实现。任务骨架从 D1 开始，D2 完成分片恢复。备份基础随 D1 落盘能力建立，D5 验证完整恢复。真实／演示隔离在 D1 首次真实页面接入前完成，D5 复验全流程。每个小阶段同步更新所需 OpenAPI、前端转换层和相关测试，不同时开发未定义的建议算法。

| DATA-07 | 非法 OHLC、字段改变、异常涨跌与空响应。 | 结构错误隔离；真实极端值不无条件删除；失败不覆盖最近成功资料。 |

| DATA-10 | 联接目标缺失／跨期、主题重叠、杠杆或分母不一致。 | 返回部分、估计或不可计算；不强行补齐 100%，不把占股票市值比当占净资产比。 |
| DATA-11 | 报告期末早于公开日；仅有公告日期或无公开时间。 | 截止时点前不可用的数据被排除；日期精度和 first_seen 保守策略生效。 |
| DATA-12 | 来源更正后又恢复旧值、换来源、分类调整。 | 每次有效变化可追溯；latest 按策略变化，原建议快照和原分类保持不变。 |
| DATA-13 | 历史回填和 public_as_of 查询。 | 新取回版本不能仅凭原日期冒充当时公开版本；重建标识与系统历史分开。 |
| DATA-14 | 小数价格、份额、费率及舍入边界。 | JSON 字符串往返无损；存储和精确计算无浮点隐式转换；未知计费规则不默认执行。 |
| DATA-15 | 分红／拆分与复权序列共存。 | 原始资料不互相覆盖；事件比例方向明确；输入元数据能阻止重复分红计算。 |
| DATA-16 | API 写入与任务同时提交，任务中途被杀死。 | 无重复事实、无半份报告发布；已提交片段保留，checkpoint 与结果一致。 |
| DATA-17 | 取消、部分失败、限流、休眠恢复及旧租约提交。 | 状态准确，失败片段可重试；旧租约拒绝写入；不虚报完成。 |
| DATA-18 | 文件写完数据库回滚、文件缺失、磁盘不足。 | 孤立文件可识别；坏引用不成为可用依据；旧数据和快照不被清理。 |
| DATA-19 | WAL 活跃时备份、损坏备份、迁移／恢复失败。 | 成套副本可独立校验恢复；损坏／不兼容副本不覆盖现有目录。 |
| DATA-20 | 正式模式断网、未开发建议／模拟、残留 localStorage。 | 本地真实数据可查看，失败不切演示；虚构建议、收益、任务与交易不进入正式结果。 |

单元测试侧重规范化、独立数值算例、版本选择和暴露；集成测试使用临时 SQLite 与文件目录，覆盖并发、幂等、任务和恢复；前端沿用现有 Vitest／Playwright，重点复验 UI-01–04、UI-10、UI-13、UI-16–17 对应的真实数据行为。数据变更影响的其他页面按实际接入范围补联调，不把演示流程通过视为业务公式通过。

### 13.2 本机性能与完成标准

在实际开发电脑记录 CPU、内存、磁盘、数据规模和测试方式。首批工程目标：10,000 个份额目录下，已建索引的本地搜索／分页接口预热后 p95 ≤ 300 ms；单对象近 3 年日序列读取 p95 ≤ 500 ms；后台采集时页面仍可读取已发布数据。指标是待验证目标，不是当前测量结果；超限先定位查询／事务，不直接换数据库。

本阶段完成需同时满足：真实目录与优先类型样本验证通过；核心页面读取持久化真实数据；历史版本与快照可复核；精度、单位、覆盖和时点标识正确；恢复与幂等用例通过；来源限制、未支持类型和数据缺口在页面及验收记录中一致。某来源缺字段可以如实限制相关能力，但不能把持仓／ETF 联接等尚未交付的核心功能整体称为已完成。

交付物为后端与前端接入代码、版本锁定与迁移文件、来源探针记录、离线测试样本、API 契约及真实数据验收报告。§3.3 开发从已验证的数据能力与缺口出发制定分析门槛；§3.4 制定账本／模拟规则；§3.5 制定研究与验证方法；§3.6 补齐日常运行体验。
