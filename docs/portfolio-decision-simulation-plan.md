# 持仓、决策记录与模拟对比：分阶段开发与复查计划

- 更新日期：2026-09-19
- 对应范围：整体技术架构 §3.4
- 设计依据：[持仓、决策记录与模拟对比开发方案](portfolio-decision-simulation-design.md)
- 当前进度：演示界面及本地草稿能力已完成并有前端测试；正式业务阶段尚未开始。研究数据库、真实行情和不可变建议可作为后续输入，但不能替代账本、计费和模拟服务。

## 1. 状态与执行规则

| 状态 | 含义 |
| --- | --- |
| 未开始 | 尚无本项正式实现。 |
| 进行中 | 已有可复用基础或部分实现，但未满足本项退出条件。 |
| 待复查 | 实现和必要自动验证已完成，等待用户复查。 |
| 已通过 | 用户已接受正式能力交付。 |
| 已完成（演示） | 仅完成明确标识的前端演示，不能用于真实记账或投资结果。 |
| 受阻 | 必要数据、接口或外部条件缺失；列明已完成部分和阻塞影响。 |

一次默认执行一个小阶段。每项同时交付数据库迁移、服务接口、调用方、测试和文档；金额、份额、日期或收益逻辑必须提供固定独立算例。写入真实个人记录前先完成备份和幂等基础，不以浏览器缓存迁移冒充正式账本导入。

## 10. 推荐实施顺序与复查入口

推荐顺序为 `P0 → P1 → P2 → P3 → P4 → P5 → P6`。P3 的界面可在 P1 后准备，但正式关联依赖 §3.3 建议修订；P4 的长任务依赖 §3.6 R2；P6 的恢复验收依赖 §3.6 R4。

每次交付至少说明：变更的表和 API、精度／时间口径、固定算例、实际运行测试、最短页面复查路径和剩余限制。只有所有正式小阶段通过后，§3.4 才能标为完成；上表 P-UI 的“已完成（演示）”不计入正式退出条件。
